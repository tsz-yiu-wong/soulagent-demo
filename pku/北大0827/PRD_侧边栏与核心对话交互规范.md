## 1. 产品概述与设计原则

### 1.1 产品定位
SoulAgent 是一款集**通用智能助手（Agent）**、**个人定制分身（My Clones）**与**行业专家分身（Expert Twins）**于一体的多智能体协同工作平台。
- **通用主 Agent**：负责通用问答与跨领域多智能体协同调度，支持随时在会话中 `@` 召唤分身或专家共同提供咨询。
- **垂直分身直聊**：提供与自建个人分身或入驻学术专家的 1v1 沉浸式深度探讨。
- **多专家协同群聊**：支持跨学科专家多对一圆桌研讨，模拟拟人化顺序时序发言。

### 1.2 核心设计原则
1. **轻量即时（Zero-Ghost-Chat 先发后建）**：
   - 用户点击“新建”或分身名片仅进入起草与引导界面，**侧边栏历史列表不会生成任何空白会话项**。
   - 只有当用户产生实质交互（发送首条有效消息）后，系统才正式提取标题建立会话，并无缝进入会话详情。
2. **场景分流（Dual-Mode Clarity 双轨清晰）**：
   - 严格区隔“主 Agent 协同对话”与“垂直分身 1v1 直聊”两种产品形态。
   - 在视觉排版、名片展示、输入工具栏（是否支持 `@`）、消息样式与上下文逻辑上保持明确的心智区隔。
3. **沉浸与引导（Smart Guidance 定制引导）**：
   - 根据 Agent 与各分身的专长定位，动态提供定制化 Prompt 气泡与人设名片，大幅降低用户提问门槛。

### 1.3 整体页面架构
全局界面由两部分组成：**左侧固定侧边栏（固定宽度 250px）** + **右侧主内容区**。
侧边栏为全局常驻导航组件，不随右侧主内容切换而折叠收起。

### 2.2 核心交互流程图

#### 流程 A：主 Agent 新建与首发流程
```
点击「新建对话」按钮 / 点击 Logo
       ↓
进入主 Agent 新建页（历史列表无变化，显示问候语与 3 张推荐卡）
       ↓
输入内容（或点击推荐卡一键填入）→ 点击发送
       ↓
提取前 20 字符生成会话标题
       ↓
创建会话记录并跳转至详情页（侧边栏历史列表顶端同步插入普通气泡会话）
```

#### 流程 B：垂直分身/专家 1v1 新建与首发流程
```
侧边栏点击分身 / 分身广场点击专家卡片
       ↓
进入该分身/专家专属新建页（居中大名片 + 3 个定制 Prompt Chips，历史列表无变化）
       ↓
输入内容（或点击 Prompt Chip 一键发送）
       ↓
创建会话记录并跳转至详情页（侧边栏历史列表顶端同步插入带该分身/专家彩色 Badge 的会话）
```

#### 流程 C：已有会话中 @ 跨分身协同咨询流程
```
打开某条主 Agent 历史会话
       ↓
输入框中点击「AI分身」选择器选择角色（或直接输入 @名字）
       ↓
发送消息
       ↓
AI 以「协同咨询」格式呈现回复：
  1. 提示语：“帮你咨询了 XX，回复如下：”
  2. 被咨询方专业解答（主题色边框引用块）
  3. 主 Agent 综合提炼与推进建议
（会话类型保持主 Agent 对话不变，历史 Badge 维持气泡图标）
```

#### 流程 D：多专家圆桌群聊流程
```
在 AI 分身广场勾选 2 位及以上专家 → 底部栏输入研讨议题并确认
       ↓
创建群聊会话（侧边栏插入红色「群聊」Badge 会话）
       ↓
进入群聊详情页，多位专家依次输出：
  1. 专家 A 思考动效 (1~1.2s) → 专家 A 观点输出
  2. 专家 B 思考动效 (1~1.2s) → 专家 B 观点输出
  3. 全部发言完毕，输入框恢复可用
```

## 3. 全局侧边栏交互规范

### 3.1 侧边栏结构示意

```
+------------------------------------+
|  [ 北大标识 / 品牌 Logo ]          |  -> 点击直达主 Agent 新建页
+------------------------------------+
|  [ ✨ 新建对话 ]                   |  -> 独立操作条（原地刷新/跳转）
+------------------------------------+
|  AI分身                            |  -> 点击跳转至「AI分身广场」
|    ├─ [诗] 我的写诗分身            |
|    ├─ [具] 我的具身AI分身          |  -> 个人就绪分身（点击进入分身专属新建页）
|    └─  +  创建分身                |  -> 点击进入创建向导
+------------------------------------+
|  历史对话                          |
|    ├─ [群聊] 具身智能架构探讨      |  -> 红色渐变「群聊」Badge
|    ├─ [专家名] 视觉算法演进探讨    |  -> 专家专属主题色 Badge
|    ├─ [分身名] 七言律诗创作        |  -> 分身专属主题色 Badge
|    └─ 💬 智能系统预测模型探讨      |  -> 默认气泡图标 (主 Agent 会话)
+------------------------------------+
```

### 3.2 区域划分与详细交互逻辑

#### 3.2.1 区域 1：Logo 品牌区
- **展示**：产品与机构标识（北大 Logo）。
- **交互**：点击直接跳转至“主 Agent 新建对话页”（与「新建对话」按钮行为一致）。

#### 3.2.2 区域 2：新建对话主入口
- **展示**：独立操作卡片，包含高亮描边与星芒图标。
- **页面状态分支**：
  | 当前所在页面 | 点击响应行为 |
  | :--- | :--- |
  | **已在主 Agent 新建对话页** | **原地不跳转**：清空当前输入框内容并聚焦，下方 3 张推荐问题卡片重新随机刷新 |
  | **其他任何页面**（详情页/分身页/广场等） | 跳转进入主 Agent 新建对话页 |

#### 3.2.3 区域 3：AI 分身体系导航组
- **“AI分身”总标题**：点击直接跳转至“AI分身广场”页面。
- **我的分身子列表**：
  - **展示规则**：仅展示当前用户已创建并**构建完成**的个人分身（处于“构建中”的分身进行隔离，不在此显示）。
  - **视觉呈现**：小尺寸圆形渐变字母头像 + 分身名称。
  - **点击行为**：点击进入对应分身的**专属新建对话页**（全新的空白起草态，未发送消息前不产生历史记录）。
- **“+ 创建分身”入口**：点击跳转至分身构建向导页面 (`persona-distill`)。

#### 3.2.4 区域 4：历史对话列表
- **排序规则**：按会话创建/更新时间倒序排列（最新会话在最上方），超出高度支持区域内平滑滚动。
- **差异化徽章（Badge）标识体系**：
  | 对话类型 | Badge 呈现形式 | 示例与色彩规范 |
  | :--- | :--- | :--- |
  | **主 Agent 协同对话** | 默认消息气泡图标（无文字） | 灰色气泡图标 `💬` |
  | **垂直专家分身对话** | 彩色胶囊标签，文字为专家姓名 | 如 `[黄铁军]`（专家主题色标签） |
  | **个人专属分身对话** | 彩色胶囊标签，文字为分身名称 | 如 `[写诗分身]`（分身主题色标签） |
  | **多专家协同群聊** | 暗红/红色渐变胶囊标签，固定文字「群聊」 | 红色渐变 `[群聊]` 标签 |
- **点击交互**：点击历史项加载完整对话历史，侧边栏对应项置为高亮激活态（`.active`）。

### 3.3 侧边栏实时响应与事件总线同步机制
侧边栏在以下业务事件触发时通过全局事件总线实时刷新，无需用户手动刷新网页：
1. **发送首条消息**：新生成的会话即刻以激活态插入到历史列表首位。
2. **分身构建完成**：后台分身从构建中状态转变为 100% 就绪时，侧边栏分身树动态新增该分身节点。
3. **分身信息变更**：在管理面板修改分身名称或头像后，侧边栏分身列表即时同步更新。

## 4. 核心对话双轨体系规范 (Dual Chat Paradigm)

---

### 4.1 主 Agent 协同对话体系

面向通用任务处理与多分身/专家协同调度。

#### 1. 主 Agent 新建对话页
- **视觉布局**：
  - **问候大标题**：居中展示亲切问候语（如：“TY，今天需要帮你做什么”）。
  - **输入容器**：多行自适应输入框，支持附件上传与键盘快捷交互。
  - **推荐问题卡片**：从题库中随机抽取 3 张技术/研究洞察卡片展示在输入框下方。用户点击任意卡片即可自动将内容填入输入框并**直接触发发送**。
- **@ 协同选择器**：
  - 工具栏提供「AI分身」下拉菜单，分组展示“我的分身”与“专家分身”。
  - 用户选中某项后，输入框头部自动插入 `@分身名 `。用户亦可直接键盘手打 `@名字`。

#### 2. 主 Agent 对话详情页
- **顶部栏**：展示会话标题，**不显示单人人设大名片**，保持大面积纯净消息空间。
- **消息气泡流**：
  - 用户提问：靠右排列，浅灰圆角气泡。
  - Agent 回复：靠左排列，通栏自然排版，不显示个人头像。
- **@ 协同咨询回复格式规范**：
  当用户提问包含 `@分身名` 时，主 Agent 按照固定协同协议输出结构化内容：
  1. **协同导语**：“帮你咨询了 XX（角色/职称），回复如下：”
  2. **分身专业观点**：以独立卡片引用块展示（带对应分身主题色的左侧粗边框）。
  3. **Agent 综合提炼与推进建议**：主 Agent 总结归纳要点，并给出下一步落地方案或实验排期建议。
- **输入栏**：持续常驻「AI分身 (@)」选择器，支持在同一会话中持续邀请其他分身协同讨论。

---

### 4.2 垂直分身 1v1 直聊体系 (个人分身 & 专家分身)

面向特定专业场景的沉浸式深度交流。

#### 1. 角色分类与权限定义
- **个人专属分身 (My Clones)**：用户自建分身，具备知识库管理与申请上架广场的权限。
- **行业专家分身 (Expert Twins)**：平台预置入驻的高校学者或行业权威，具备公开职称、研究方向与权威学术背景。

#### 2. 分身专属新建页
- **居中人设大名片**：
  - 大尺寸圆形头像（个人分身为专属文字头像，专家为肖像/人形图标）。
  - 分身名称与身份标签（如：粉色 `专属AI分身 · 我的分身` 或 红色 `教授 · 博士生导师`）。
  - 结构化标签栏（职称标签 + 专业研究领域标签）。
  - 详细的专长简介与背景说明。
- **定制 Prompt 气泡（Prompt Chips）**：
  - 名片下方展示 3 个专为该分身量身定制的提问气泡（如写诗分身提供“创作七言绝句”，具身分身提供“控制架构设计”）。
  - 用户点击气泡即刻自动填入并直接发送。
- **自适应输入框**：占位符动态变更为 `给 {分身名} 发送消息...`。
- **顶部操作栏权限差异**：
  - **个人分身**：
    - **[管理分身]**：点击跳转至分身广场中的管理面板。
    - **[申请上架到 AI 分身广场]**：三态流转（见下文 5.3 节）。
  - **专家分身**：
    - 显示 **[返回 AI 分身广场]** 导航链接。

#### 3. 分身对话详情页
- **顶部常驻名片**：消息流最顶端保留该分身的名片卡与 3 个 Prompt 气泡，便于用户随时回顾人设或追问。
- **1v1 沉浸式气泡流**：
  - AI 回复左侧带有该分身/专家的专属头像与姓名，回复口吻严格遵循其设定的人设第一人称。
- **工具栏极简隔离**：
  - 底部工具栏**自动隐藏「AI分身 (@)」按钮**，禁止在单分身会话中引入其他分身，确保 1v1 纯粹性。

### 4.3 衍生模式：多专家协同群聊

- **发起机制**：在分身广场勾选 2 位及以上专家，点击底部悬浮栏“发起群聊”并输入共同议题。
- **侧边栏标识**：生成带红色渐变 `群聊` 徽章的会话记录。
- **拟人化时序发言机制**：
  - 详情页不显示单人名片。
  - 多位专家按照拟人化时序**依次发言**：
    1. 显示当前专家的思考打字动画（`正在思考并组织见解...`，持续约 1.0~1.2 秒）。
    2. 渲染输出该专家的学术观点（带专属彩色头像、姓名与职称）。
    3. 自动触发下一位专家思考并输出，形成圆桌研讨的视觉体验。
  - 在所有专家完成发言前，底部输入框置灰禁用，防止并发错乱。

## 5. AI 分身广场与分身生命周期管理

**入口**：点击侧边栏「AI分身」标题。

### 5.1 页面两大 Tab
| Tab 名称 | 功能定义与展示内容 |
| :--- | :--- |
| **AI分身广场** | 平台所有公开专家分身卡片流（头像/姓名/职称/领域/简介/对话数），支持卡片点击直聊与多选群聊 |
| **我的分身** | 个人专属分身管理控制台（左侧分身列表 + 右侧 5 大配置子 Tab） |

---

### 5.2 我的分身管理控制台 (5 大子 Tab)

左侧为当前用户自建的分身列表（含构建中与已完成），点击切换右侧详情面板：

```
+-----------------------------------------------------------------------+
| 我的分身列表          | [基本信息] [知识库] [设置] [总结] [历史会话]       |
| ├─ [诗] 写诗分身      |                                               |
| ├─ [具] 具身智能 (构建中) |                                               |
+-----------------------------------------------------------------------+
```

1. **基本信息 Tab**：编辑分身名称、头像、职称头衔、研究领域、所在院系、个人简介、个人主页链接。
2. **知识库 Tab**：管理分身知识挂载，支持四种导入渠道：
   - 本地文件上传（PDF / Word / Markdown / TXT）
   - 网页链接爬取
   - 网盘链接同步
   - 微信公众号订阅
3. **设置 Tab**：
   - AI 系统人设与 Prompt 配置
   - 初始欢迎语设定
   - 推荐提问配置（支持手动添加或 AI 智能提取生成）
   - 禁答范围与安全边界设定
   - 联网搜索开关 / 语音通话开关 / 声音克隆配置
4. **总结 Tab（仅已上架分身可见）**：分身对外接待访客的数据分析看板（累计访客数、交互轮次、高频热门话题分布、内容安全检测报告）。
5. **历史会话 Tab（仅已上架分身可见）**：查看公开访客与该分身的匿名/公开聊天记录，支持对话回溯与质量评估。

### 5.3 分身生命周期与状态流转

#### 1. 构建状态流
```
创建分身提交 → 「构建中」（进度条 0% → 100%）→ 「已完成」（就绪可对话）
```
- **构建中状态**：侧边栏分身树不展示；广场管理面板中显示进度条并置灰不可对话。
- **已完成状态**：侧边栏自动注入该分身入口，可正常发起 1v1 对话或在 Agent 中被 `@` 召唤。

#### 2. 广场上架与审核流
```
私密状态（仅自己可见） ──[点击申请上架]──> 提交申请表单 ──> 审核中（按钮禁用）
                                                                 │
                                                            审核通过
                                                                 ↓
私密状态 <──[主动下架(需弹窗二次确认)]── 公开上架至广场（启用「总结」与「历史会话」Tab）
```

- **申请上架交互**：
  | 状态 | 按钮显示态 | 交互说明 |
  | :--- | :--- | :--- |
  | **未申请** | `申请上架到AI分身广场`（高亮可点） | 点击弹出申请弹窗，录入联系人与申请说明后提交 |
  | **审核中** | `上架审核中`（置灰禁用） | 提示平台管理员正在审核中 |
  | **已上架** | `已上架至广场`（绿色状态徽章） | 呈现公开状态，开启数据统计与访客会话面板 |

### 5.4 创建分身向导流程 (persona-distill)
**入口**：侧边栏「+ 创建分身」或分身广场「创建分身」按钮。
- 采用多步骤向导式引导用户录入：基本资料设定 -> 知识库挂载 -> 性格特征提炼 -> 确认创建。
- 提交后系统自动异步执行提炼任务，分身进入“构建中”生命周期。

## 6. 全局业务规则与边界交互

### 6.1 会话命名与防重规则
1. **自动摘要提取**：
   - 默认截取首条用户输入的前 20 个字符作为会话标题。
   - 若首条提问以 `@分身名` 开头，系统自动去除 `@` 标识符及空格，仅截取纯业务提问文本作为标题。
2. **重名自增防冲机制**：
   - 若历史列表中已存在同名会话，系统自动在标题末尾递增数字标识，如 `多模态大模型架构 (1)`、`多模态大模型架构 (2)`，确保会话可唯一寻址。

### 6.2 输入与发送交互规范
1. **空内容拦截保护**：输入框为空或仅有连续空格/换行时，发送按钮置灰禁用，快捷键响应被拦截。
2. **快捷键标准**：
   - `Enter`：立即发送当前输入内容。
   - `Shift + Enter`：在输入框内换行，不触发发送。
3. **防重复提交机制**：
   - 正在等待 AI 流式输出、协同分身回复或群聊多专家时序发言过程中，输入框与发送按钮置灰禁用，避免乱序提交。

### 6.3 状态隔离与全局事件保护
1. 处于“构建中”的分身严禁出现在侧边栏导航列表中，彻底杜绝用户误进入半成品空白会话。
2. 广场管理面板下架分身后，该分身对外公开服务即刻终止，但用户私有对话权限与历史会话数据完整保留。
