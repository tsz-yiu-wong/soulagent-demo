# 主办方管理后台 - 业务逻辑与页面架构梳理

根据系统流程图（会前、会中、会后 Agent 协作链路），针对主办方管理后台进行底层业务逻辑拆解、页面划分及关键交互设计。

---

## 一、 底层核心实体与依赖关系 (Entity Relationships)

```
[活动 Event]
   └── [论坛 Forum] (1:N)
        ├── [直播/音视频流 Live Stream] (1:1)  <-- 信号物理通道绑定在论坛层级
        └── [议题 Agenda Item] (1:N)            <-- 时间轴上的内容节点
             ├── [讲者/嘉宾 Speaker] (N:N)
             └── [ASR 动态修正状态 ASR Sync State] (1:1)
```

1. **论坛 (Forum) 与 直播流 (Live Stream)**：1对1绑定。直播流是会场/论坛的物理信号输入源；ASR 哨兵 Agent 也是挂载在论坛级别的直播流上进行监听。
2. **论坛 (Forum) 与 议题 (Agenda Item)**：1对多。议题是论坛时间轴上的具体演讲/环节。
3. **议题 (Agenda Item) 与 讲者 (Speaker)**：多对多关联。
4. **议题 (Agenda Item) 与 ASR 动态数据**：会中 ASR 转录 Agent 及修正 Agent 对议题的实际起止时间、讲者声纹识别、文本摘要进行实时比对与纠偏。

---

## 二、 后台页面划分 (Page Architecture)

建议将主办方管理后台划分为以下 **4 个核心页面/模块**：

| 页面名称 | 核心职责 | 对应系统流程阶段 |
| :--- | :--- | :--- |
| **1. 论坛与直播配置 (Forum & Live Stream)** | 配置论坛基本信息、绑定直播/拉流/重播地址、监控信号源状态 | 会前/会中 |
| **2. 议程与 ASR 动态校准 (Agenda & ASR Correction)** | 静态议程编排（时间/议题/讲者），及会中基于 ASR 智能识别的实时议程校准与确认 | 会前/会中 |
| **3. 嘉宾/讲者库 (Speaker Management)** | 讲者信息管理、图文/解析 Agent 校验结果确认 | 会前 |
| **4. 会后资产与 AI 运营 (Post-Event Assets & AI Ops)** | 会议纪要审阅、矢量知识库沉淀（问答）、风格化宣发文案生成与发布 | 会后 |

## 三、 核心交互逻辑 (Key Interaction Flows)

### 1. 配置论坛 vs 配置论坛内议题的交互

- **解耦逻辑**：直播/拉流地址绑定在**论坛（会场）**，而非单个议题。因为直播流是连续的信号通道，议题是时间轴切片。
- **交互形式（主从结构 Master-Detail / 抽屉 Drawer）**：
  1. **论坛层**：主列表展示各论坛卡片（如：主论坛、分论坛A），直观显示当前论坛的直播流状态（推流中/未开始/拉流URL）。
  2. **议题层**：点击进入某论坛详情，页面分为上下或左右结构：
     - **顶部/侧边**：配置论坛基础信息（论坛名称、时间、直播拉流地址、重播地址）。
     - **主体区域**：以**时间轴（Timeline）/ 列表**展现该论坛下的议题列表。
     - **议题操作**：在时间轴上新增/拖拽排序议题，配置议题标题、计划起止时间、选择绑定嘉宾（支持多选）、上传议题PPT/资料。

---

### 2. 议程根据 ASR 转录自动修正的交互

- **底层机制**：会中哨兵 Agent 抓取论坛直播流 -> ASR 转录 + 声纹识别 -> 比对预设议程的时间与讲者 -> 产生修正建议。
- **交互设计**：
  1. **实时状态感知**：
     - 议程列表中，当前正在进行的议题高亮显示 `[Live 进行中]` 标识及 ASR 实时转录文本流（抽屉查看）。
  2. **双轨对比与预警提示（Diff & Alert）**：
     - 当 ASR 识别结果与预设议程存在偏差（如：**讲者不符/临时代讲**、**会议拖堂/提前**）时，对应议程卡片出现 `[ASR 动态校准建议]` 警告提示框。
     - 显示对比视图：
       - **预设配置**：14:00 - 14:30 | 讲者：张三 | 《大模型实践》
       - **ASR 识别**：14:05 - 14:45（拖堂15分钟） | 声纹识别讲者：李四
  3. **修正控制策略**：
     - **低风险/时间微调（可开启自动同步）**：提供全局/单论坛开关 `[ASR 时间自动纠偏]`。若开启，ASR 识别到议题实际结束时，自动顺延后续议程展示时间。
     - **高风险/人员身份变更（人工一键确认）**：系统生成修正卡片，主办方可选：
       - `[一键应用修正]`：自动更新议程信息（同步更新官网/小程序前端展示）。
       - `[忽略]`：保持预设议程不变。
